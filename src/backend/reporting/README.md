# backend/reporting

Renderers for review deliverables. They are pure output functions: they take already assembled
objects and write files. Assembly of the report content happens in `services/report_service.py`.

## Purpose and responsibility

* Machine-readable assessment JSON.
* A PDF assessment report built programmatically with ReportLab.
* ADR (Architecture Decision Record) drafts in Markdown.

## Modules

| File | Functions | Output |
| --- | --- | --- |
| `json_generator.py` | `write_json_report(report: AssessmentReport, path) -> int` | `*.json`; written to `*.json.part`, re-validated with `AssessmentReport.model_validate_json`, then atomically renamed |
| `pdf_generator.py` | `build_pdf(report: AssessmentReport, path) -> int` | `*.pdf` (A4, Helvetica standard fonts); written to `*.pdf.part` then renamed |
| `adr_generator.py` | `build_adr(review, finding, *, kind, number, decision, determination) -> ArchitectureDecisionRecord`, `render_markdown(...)`, `slugify()` | ADR model with `markdown` text; the file itself is written by `DecisionService.ensure_adr` |
| `templates/` | empty | See `templates/README.md` |

### PDF structure (`build_pdf`)

Title block with a SIMULATED DEMO banner for demo reviews; summary table; 1 Executive summary
(narrative, major risks, clarifications); 2 Scorecard table and per-domain explanations; 3 Findings
grouped in the fixed order security, resilience, finops, compliance, performance, operability (one
`_finding_block` per finding with explanation, scenario, impact, recommendation, evidence,
principle, moderator notes, architect decisions and remaining risk; critic rebuttals appear in the
JSON report but not in the PDF); 4 Architect
decision history; 5 ADRs; 6 Recommendations; 7 Review history and coverage (rounds, revisions,
agent and tool status); 8 Limitations and caveats. A footer carries the architecture name, review id
and page number. `_safe()` escapes ReportLab markup and folds characters outside Latin-1.

### ADR kinds (`build_adr(kind=...)`)

| `kind` | Title prefix | Source |
| --- | --- | --- |
| `DEFERRED_RISK` | `Defer remediation:` | An architect DEFER decision (owner, review date, remediation target) |
| `ACCEPTED_FINDING` | `Adopt remediation:` | An accepted CRITICAL/HIGH/MEDIUM finding at finalization |
| `DISPUTE_RESOLUTION` | `Disposition of disputed finding:` | A dispute upheld through rebuttal and moderator determination |

ADRs are always `PROPOSED` drafts requiring architect approval and carry a SIMULATED DEMO banner
when the review is simulated.

## Inputs and outputs

* Input: `AssessmentReport` (`models/schemas.py`), or `Review` + `Finding` + optional
  `HumanDecision`.
* Output files (paths chosen by `DataPaths`/`ReportService`):
  `data/reports/<review_id>/architecture-review-<review_id>-rev<N>-<timestamp>.{json,pdf}` and
  `data/reports/<review_id>/adrs/ADR-<nnn>-<slug>.md`.

## Dependencies

`reportlab`, `models.domain`, `models.schemas`. No dependency on services (services depend on this
package).

## Role in application execution

`finalize` node -> `ReportService.generate` -> `write_json_report` + `build_pdf`;
`POST /reviews/{id}/reports` and `GET /reviews/{id}/report-preview` use the same assembly.
ADRs are generated by `DecisionService` on DEFER decisions, on dispute resolution (`rebuttal` node)
and at finalization.

## Extension points

* New output format (for example HTML or Markdown): add `<fmt>_generator.py` with
  `build_<fmt>(report, path) -> int`, handle the new format name in `ReportService.generate`, and
  extend `reports.generate_reports`/the media type map in `reports.download_report`.
* New report section: extend `AssessmentReport` / `ReportService.build`, then render it in
  `pdf_generator.build_pdf`.
* New ADR kind: add a branch in `build_adr` and the prefix map in `DecisionService.ensure_adr`.

## Limitations

* Standard Helvetica fonts only: non-Latin-1 text is replaced with `?`.
* The PDF is a linear document; there is no table of contents, charts or embedded diagrams.
* ADR numbering is `len(existing) + 1` per review; ADRs are not renumbered.
* The domain order in the PDF is hard-coded to the six built-in agents.
